# 建模方法论与学科纳入标准

## LM 的核心方法论：耦合，不是堆叠

LM 存在的理由是把多篇独立文献各自验证过的机制放进同一个模型，让原本分散在不同论文里、互不知晓彼此存在的机制产生真实的相互作用，从而显现出单篇论文各自的建模范围内看不到的权衡。这是本项目区别于逐篇复现单一研究结论的核心价值，也是判断一个模型该不该纳入更多机制、以及已经纳入的机制该不该保留的唯一标准。

判断一次机制组合是否成立，看的不是混入了几篇文献、几个既有模型，而是这些机制之间有没有一条决策变量必须真实取舍的通路。某个决策变量的收益如果只在一个目标上体现，在其余目标上完全没有代价，这条机制就还是孤立的，不构成耦合，即使它旁边同时并存着另外三五个同样孤立的机制，模型整体看起来维度很多，也不会产生额外的权衡信息，只会让 Pareto 前沿在多个互不相关的方向上分别退化。真正的耦合要求至少两个机制共享同一份有限资源，或者一个机制的输出是另一个机制的输入，使得优化器在其中一个目标上的每一次改进都必须在另一个目标上付出可衡量的代价。

据此，机制数量本身不是纳入标准，也不是拒绝标准。窄而深的单机制模型，把一条动力学的系数和轨迹做到能用独立于拟合数据之外的另一批测量值做留一法验证，达到的证据等级本身就高于多个机制放在一起、只验证前沿本身自洽这种组合模型能达到的证据等级，二者是两种并行有效、互不替代的验证目标，不存在窄的必须被拉宽、宽的必须被验证到窄的单向要求。反过来，如果一个模型已经混入了多个机制，其中某个机制和其余部分之间找不到真实的资源竞争或因果通路，正确的处理方式是把它从模型里剔除，而不是保留下来充数。一个和其余机制毫无关联的维度留在模型里，不会增加信息量，只会增加决策变量数量、拖慢搜索、并在前沿里制造无意义的自由漂移。

新增或审查一个模型时，按以下问题自查：

- 这个决策变量的收益，有没有在任何其他目标上产生对应的代价，还是只是单向地越多越好？
- 如果把这个决策变量推到它的边界，其余目标会不会跟着变差，还是完全不受影响？
- 模型里的多个机制，有没有共享同一份有限资源，或者一个机制的输出接入另一个机制的输入？
- 如果某个机制拿掉之后，其余机制产出的前沿结构没有任何变化，这个机制是不是应该被移除？

## 模型纳入标准（Inclusion Criteria）与学科覆盖盘点（2026-07-29 新增）

LM 从"要不要为某个学科/某个声称建模"到"论文里能不能引用"，经过纳入、评估、输出三个阶段：本节对应纳入阶段——决定值不值得投入建模精力；评估阶段的六阶段流程、四维归因分类和逐模型判定见 `models/test_validation/validation_report.md`；输出阶段指论文只引用评估阶段确认通过的模型，见该文件"论文模型盘点"一节按 S1-S4 分类的选型结论。

这四问的英文正式表述已写入 `docs/LM_format_1.0.md` 的 Scope 一节（Inclusion Test），作为格式规范本身对"什么话题落在 LM format 范围内"的操作化定义；本节的四问、符号约定和盘点表是该定义在本项目模型库里的具体落地和持续追踪，不是另一套独立标准。

下方盘点表里大量表示尚未评估的 `?` 格子如实反映了模型库的真实状态——本项目模型库大部分内容由 AI 辅助生成与初步复核，尚未经过相关领域专家核实，作者本人的核实精力集中投入在少数 `confidence` ≥ 0.75 的核心示范模型上（`docs/authoring/ratings.md` 0-1 量表，`models/papers/lm_format/`、`models/plan/` 下已按此标准打分，其余目录暂沿用未迁移前的旧记录）；完整的责任边界声明见仓库 README「内容可信度声明」一节。

### 四问粗筛

纳入判断落在 LM 的四个使用位置，每个位置对应一个能否成立的问题：

- **var**：该学科的声称是否有可迁移的具体数值（效应量、速率常数、剂量-反应系数等），而不是只有"有影响""相关"这类方向性描述？
- **equ**（`equations`）：该机制是否存在公认的函数形式（微分方程、回归方程、动力学方程）可以直接编码，不需要建模者现场发明结构？
- **sim**：编码后的机制能否产出随时间演化、可以跟独立数据点比对的轨迹，而不是只能做静态数值展示？
- **opt**：该学科的决策空间里是否存在真实的多目标权衡（不是单一最优解），值得跑 optimizer？

前两问（var/equ）决定这个学科的声称值不值得编码进 LM，任一不通过说明素材本身撑不起一个可执行模型，不该投入建模精力；后两问（sim/opt）决定编码完之后能拿这个模型宣称到什么程度，var/equ 通过但 sim/opt 用不上时模型依然成立，只是使用方式受限于机制/引擎正对照展示，不能做独立预测或优化（量表定义见 `docs/authoring/ratings.md` 的 `confidence`）。

`models/test_validation/validation_report.md`《尝试但未构建的学科》一节记录了具体候选案例层面（不是整个学科层面）已经被四问粗筛淘汰的例子（如 Bass 技术扩散模型因 p/q 参数来源不可信、Lanchester 平方律因原始逐日兵力数据未能公开获取），可作为如何应用这四问的参考样本。

### 符号约定

盘点表复用 `validation_report.md`"验证判定总表"的三态符号，并新增第四态 `?`；含义在学科粒度上做了调整：

| 符号 | 含义 |
| --- | --- |
| √ | 该学科至少有一例模型在此维度验证通过，见对应小节 |
| × | 已尝试建模，走完了评估流程，但此维度未通过，诊断记录见 `validation_report.md` 对应小节 |
| - | 已确认该维度不存在可评判对象（如模型没有声明机制、没有决策变量），是"确认不存在"，不是"没评估"；只代表这一具体案例，不代表整个学科排除这种使用方式 |
| `?` | 尚未评估——跟 √/×/- 同一优先级的独立状态，不是留白：学科方向已确定或已有模型文件，但还没有走过纳入/评估流程，不能默认读成"不适用"（-）或"已通过"（√） |

`?` 和 - 的区别决定了怎么读这张表：- 是"查过了，确认没有"（比如一个模型只声明了静态效应量，从头到尾没有 `equations:` 块），`?` 是"还没查"（比如一个学科已经有能跑通 `--sim`/`--opt` 的模型，但没人去核对过它的机制数值对不对得上独立文献）。把这两者分开，是因为"这个学科没有可用的机制"和"这个学科的机制我们还没验证"是两个后果完全不同的结论——前者说明这条路子走不通，后者只是工作量问题。同一行内如果不同模型判定不同，用"／"分隔，不强行合并成一个符号（沿用 `validation_report.md`"汇总"表的写法）。
